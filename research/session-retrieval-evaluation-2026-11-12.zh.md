# 会话检索效果分析与回归验证

分析对象：`session-8c3bd346-8a1d-4359-9a4a-ed2d3e7a159f`，固定在首次观察的 `asOfSeq: 481`。后续新增事件不在本次统计内。基线为已发布的 Session Fleet 0.3.0，对应提交 `5c1259b`。

## 产品目标与决定

Session Fleet 负责让 Agent 在宿主允许访问的会话中找到相关上下文、取得可引用的原始证据，并通过原生队列与其他会话协作。全文索引是可选的加速能力。用户已经给出一个会话 ID 后，读取和定位该会话中的证据不应被全局索引的开关阻断。

因此保留五个工具和现有队列，补齐两个发现层次：先利用宿主已有标题提示缩小候选，再对选定会话复用宿主的语义文档和字面文本过滤。索引可用时继续走既有检索路径，关闭时明确标记字面匹配，不新增索引，也不自动扫描所有会话正文。

## 实现及契约

- `list_sessions.query`：1–500 个 UTF-16 代码单元，不区分大小写的标题字面子串。先经过宿主可见性和子会话策略，再筛选、排序、分页。游标同时绑定标题条件，查询不同但命中集合相同也不能混用。
- `search_sessions`：继续搜索有索引的当前消息。只有已知的 `SESSION_QUERY_SEARCH_DISABLED` 才附加可执行的标题恢复示例，其他错误保持原有诊断。
- `inspect_session` 搜索：已知索引停用时，从单个原生快照生成宿主语义文档，使用原生字面过滤函数。结果带 `searchMode: "literal"`，按事件顺序返回，并把片段放在匹配位置附近。原生头身份、子会话来源和当前活动 step 的排除仍被检查。
- 概览：最近输入区分真实对话和机器上下文，最后回复跳过无文本或空白文本的工具调用消息。计数仍表示原始事件数量，不把上下文事件从历史中删除。

实现入口见 [会话工具](../src/index.ts)、[原生检查](../src/inspection.ts) 和 [发现游标](../src/discovery.ts)。使用契约同步到 [英文说明](../README.md) 与 [中文说明](../README.zh.md)。

完整套件 89 个测试通过，宿主支持窗口、TypeScript、lint、Prettier 与构建通过。针对新增检索流程，还通过构建后的 JavaScript 入口运行同一组回归。

审查时故意把降级错误门禁的 `||` 改成 `&&`，存储故障被错误地转换成空结果，回归测试随即失败；条件已恢复。另从最低支持版本 `@deepseek-ai/dsh-session-query@0.2.0-rc.2` 的发布包核对所用原生函数、错误码及 `readSession` 声明均已存在。这是接口核对，不等于该旧宿主完整运行验收。

在 `maxListRows: 50`、`maxMessageChars: 20000` 下，五个工具名称、描述和输入参数规范的紧凑 JSON 从 3,869 增至 4,080 个字符，净增 211 个字符；UTF-8 从 3,875 增至 4,088 字节。策略提示未增加。这只衡量输入声明，不含 SDK 生成的输出类型，也不是模型 tokenizer 的 token 数。

## 当前 DSH 接入验证

当前 Profile 的 bundle source 是本代码库的本地链接，Loader entry 为 `include:tool-session-fleet`。重新构建后，实时工具目录包含 `list_sessions.query` 和关闭索引时的原生字面搜索说明。包版本仍为 `0.3.0`，接入判断依据是实时行为，而非版本号。

实测标题“部署”匹配 17 个会话，首屏返回 10 个且每个标题都匹配。目标会话的新概览只包含三条实际用户输入，最后文本回复为 seq 953，读取边界为 seq 957。全文搜索仍如配置所示被停用，错误提供标题恢复调用；单会话搜索返回 `searchMode: "literal"`，片段包含查询词，继续读取 seq 11 得到原始用户消息。这些测试通过当前会话的真实工具完成，没有向目标会话投递消息。

已通知用户可在当前 DSH 中体验“找出标题包含部署的会话，读取最相关会话中的原始证据”，或重新发起自托管简报请求。

## 实际边界

这是脱敏重放和使用测试模型适配器的真实 AgentLoop 验证，不是自然语言模型多轮选择工具的成功率评测，也没有证明原简报总耗时会下降到某个数值。标题可能缺失，标题匹配不能代替跨会话正文搜索。字面降级仍需解码并处理选定会话的完整原生快照。

本轮不改变部署主动关闭索引的配置。旧入口的超时、程序自行裁剪 JSON 导致信息丢失、等待预算与任务认领顺序，仍需由相应调用方改正。
